# 扩库管线(放仓库里,防止 scratchpad 被清空后丢失)

## 一轮标准流程
1. **定名单** `names*.json`:`[["中文名","英文维基条目名"],…]`
   - 定名单前必须先做馆藏核查(见下)
2. **抓取** `python3 fetch.py names1.json works1.json`
   - 用英文维基条目 pageprops 反查 QID(比 wbsearchentities 可靠得多)
3. **选件**:从 works*.json 里挑,写成 `pick*.json`
   - 每条 `{id,zh,qid,img,y,loc,a}`
   - **优先挑 sitelinks 2-9 的冷门作品**:库里已收的都是名作,冷门天然不撞车
   - 每位艺术家最多 6 件
4. **下载** `python3 dl.py pick39.json`(三级兜底:Commons缩略图→wsrv代理→原图)
5. **审图** `python3 -c "from sheet import make; ..."` 拼表 → 用 Read 工具肉眼看
6. **写卡** `cards*.py`:每张三句话(bg背景/how方式/why意义)+more
7. **烘焙** `python3 bake.py cards39a`
8. **校验+提交**:osascript 查总数与重复 id → git commit push

## 硬规矩
- 一卡一作品(不要门类卡)
- 主图必须是**作品本身**,不是作者肖像/展厅照;宁缺毋滥
- 文案不虚构;正文引号用「」不用半角(会破坏 Python 字符串)
- 新卡不写 wiki 字段(会触发外部取图)
- 日本画 cat 用「东方艺术」
- 长卷必须用局部图并在 more 注明「配图为长卷局部」
- 展厅实拍要裁到画心
- **画面与标题对不上时,先查是不是取错了作品**,而不是只换图

## 排重(头号天敌:音译分裂)
选件前先按标题在 data.js 里查:t2s 转简体 + 去括号/标点 + 排序字符指纹。
但**跨译名的同一作品查不出来**(欧菲莉娅/奥菲莉娅、黛芙妮/达芙妮、勃拉克/布拉克)。
所以:新艺术家先用 2-3 种常见译法各查一遍;姓氏词根也查一遍。

## 已知坑(踩过的)
1. **英文标题绕过中文查重**:Wikidata 返回英文标题时,`clean()` 的中文指纹匹配不到库里的中文卡。
   已在 pick.py 加 `EN2ZH` 关键词映射兜底,但**覆盖不全**——选件后仍要按作者在 data.js 里 grep 一遍。
   典型漏网:莫里索 The Psyche mirror=《穿衣镜》、Port at Lorient=《洛里昂港》。
2. **Wikidata 的 P18 图可能与标题不符**:同一 QID 挂错图,或标题指的是另一件作品。
   审图时**画面与标题对不上,先怀疑取错作品**,不要只换图。批47 马尔凯有四件如此。
3. **下载可能得到损坏图**(纯色块/彩条):sheet 里一眼可见,直接撤图。
4. 长卷/超宽作品缩略图会成细线;原图分辨率过低(高<100px)等于没图——都要换局部图或撤。
5. `bake.py` 只按 id 判重,**不查标题**;重复的判断责任全在选件阶段。
